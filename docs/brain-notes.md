# 뇌 시뮬레이터 노트 (Phase 2)

## 1. 전처리

```bash
cd server
.venv/bin/python -m flymax.brain.preprocess --profile compact   # 약 6초, 최대 메모리 약 4.3GB
```

설정은 `server/flymax/config/brain.yaml`에 있다.

| 프로필 | 경로 길이 H | 최소 시냅스 | 입력 상한/뉴런 | 뉴런 | 연결(nnz) | 배치 1 속도 | 배치 16~32 속도 |
|---|---|---|---|---|---|---|---|
| **compact** (기본) | 4 (버섯체 3) | 5 | 64 | 21,251 | 239,627 | 실시간의 약 12배 | 약 28배 |
| medium | 5 (버섯체 4) | 5 | 64 | 83,840 | 1,856,397 | 약 1.7배 | 약 3.9배 |
| full | 전체 Traced | 3 | 제한 없음 | 165,122 | 약 1,000만 | 학습에는 부적합 | |

속도 측정 환경은 Apple M4, 10코어다. 단위는 "게임 시간(초) / 실제 시간(초)"이다.

- **기본값은 compact로 정했다.** 강화학습은 수백~수천 판을 돌려야 하므로 실시간보다 충분히 빨라야 한다.
- compact도 시각 입력 L1/L2 3,534개, 다리 운동 뉴런 197개, 버섯체 회로(KC 4,064 · MBON 97 · PAM 316 · PPL1 16)를 모두 포함한다.
- 그룹 크기(레인별 입력 뉴런 수 등)는 `data/processed/<profile>/meta.json`에서 확인할 수 있다.

## 2. 모델

```
τ dr/dt = −r + tanh(relu(gain · Ŵ r + I_input + bias))
Ŵ[post, pre] = sign(pre) × synapses / (Σ|post 의 입력 시냅스|)^α
```

- 부호는 `consensus_nt`로 정한다. ACh는 +, GABA·Glu·histamine은 −, 도파민 등 조절성 전달물질은 0으로 두어 빠른 전달에서 뺀다.
- 레인마다 시각 입력 뉴런을 세로 4칸(`vertical_bins`)으로 나눈다. 노트가 화면 어디쯤 있는지가 어느 뉴런 묶음을 자극할지를 정한다.
- 행렬 곱은 **scipy CSR**로 한다. torch sparse CSR보다 배치 1에서 약 9배 빨랐다. MPS는 희소 CSR을 지원하지 않는다.

## 3. 파라미터 탐색 결과 (compact)

`python -m flymax.brain.bench`로 다시 확인할 수 있다.

| α | gain | bias | 결과 |
|---|---|---|---|
| 1.0 | 1.0 | 0 | 신호가 운동 뉴런에 거의 닿지 않음 (운동 평균 0.0002) |
| 1.0 | ≥1.3 | 0 | 입력을 꺼도 활동이 남음 (지속 활성 22~35%) |
| 0.5 | 0.2 | 0 | 전달은 되지만 지속 활성 27% |
| **0.5** | **0.25** | **−0.15** | **전달됨, 입력을 끄면 약 100ms 안에 대부분 가라앉음 (채택)** |
| 0.5 | 0.4 | −0.3 | 운동 뉴런 활동이 입력과 상관없이 커짐 |

- 정규화를 약하게 하고(α=0.5) 음의 bias(발화 문턱)를 주는 조합이 "전달은 되고 폭주하지 않는" 영역이었다.
- **한계 1: 레인 선택성이 약하다.** 레인 0 입력이 레인 0 다리 운동 뉴런만 켜지는 식의 깔끔한 대응은 없다. 실제 초파리에서 망막 위치와 다리가 직접 연결돼 있지 않으니 당연한 결과다. 그래서 모드 B·C에서는 **운동 뉴런 197개 전체 활동 → 키 입력**으로 가는 리드아웃을 학습한다.
- **한계 2: 약한 잔류 활동이 있다.** 여러 레인을 연속으로 자극하면 약 4%의 뉴런이 활동을 유지하는 상태로 들어갈 수 있다. 그래서 에피소드(곡)마다 상태를 0으로 초기화한다.

## 4. 버섯체(모드 C용) 처리

모드 C는 Kenyon cell(KC) → MBON 시냅스를 바꾸는 방식이다. 그래서 KC에 시각 정보가 실려 있어야 한다. 기본 설정에서는 KC가 거의 활동하지 않았다(4,064개 중 13개). 원인과 처리는 다음과 같다.

| 문제 | 처리 (`brain.yaml`, `preprocess.py`) |
|---|---|
| KC 입력의 대부분이 KC→KC 연결이다. 이득을 조금만 올려도 KC 전체가 폭주한다(90% 활성) | **KC→KC 연결 제거** |
| KC가 받는 시각 입력은 약한 시냅스가 많다. 그래서 `min_weight 5`와 `상위 64개 입력` 제한에 걸려 잘려 나간다 | KC 입력과 KC→MBON 연결은 **시냅스 ≥ 2까지 남기고 상위 k 제한을 하지 않는다** → KC→MBON 51,085개 |
| 정규화된 입력이 작아서 KC가 문턱을 넘지 못한다 | `kc_gain: 10`, `kc_bias: 0.15`(KC에서는 전역 문턱 상쇄) |
| 희소 코딩이 필요하다 | APL 뉴런의 피드백 억제를 근사한다. `kc_sparsity: 0.05`이면 매 순간 상위 5% KC만 활성(k-WTA) |

이렇게 처리하면 시각 투사 뉴런의 입력을 받는 KC 약 75~180개(주로 `KCg-d`, `KCab-p`)가 노트 타이밍에 반응한다. 이 KC들에서 선형 디코딩한 AUC는 0.9 이상이다.

## 5. 리드아웃별 정보량 (선형 디코딩, compact)

"지금 이 레인을 눌러야 하는가"를 뉴런 활동에서 ridge 회귀로 읽어낸 AUC다(레인 0~3).

| 뉴런 집단 | AUC |
|---|---|
| 다리 운동 뉴런 197개 | 0.96 / 0.88 / 0.71 / 0.99 |
| 하행 뉴런 292개 | 1.00 / 0.95 / 0.81 / 0.99 |
| 시각 입력 L1/L2 | 1.00 (모든 레인) |
| MBON 97개 (KC 처리 후, kc_gain 10) | 0.93 / 0.84 / 0.65 / 0.91 |

그래서 모드 B는 **다리 운동 뉴런 + 하행 뉴런**을 리드아웃으로 쓴다. 이 특징으로 지도학습한 선형 디코더를 정책으로 쓰면 정확도는 약 70~85%다. 이 값이 선형 리드아웃으로 기대할 수 있는 상한의 참고치다.
